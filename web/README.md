# Подоконник — сайт (веб-приложение)

Коллекция растений с графиком полива, база знаний по 244 комнатным растениям, лента садоводов
с подписками, лайками и комментариями, новости, распознавание по фото и достижения.
Работает в браузере на телефоне и компьютере; можно «установить» на главный экран (PWA).

Сайт статический (Next.js, `output: "export"`): собирается в `out/` и размещается на любом
хостинге — GitHub Pages, Vercel, Netlify. Данные пользователя браузер берёт напрямую из
Supabase, а права доступа проверяют RLS-политики в базе. Страницы видов базы знаний
собираются заранее, чтобы их находили поисковики.

## Запуск на компьютере

```bash
cd web
npm install
npm run dev            # http://localhost:3000
```

Без настроек сайт работает в **демо-режиме**: данные хранятся в браузере, сервер не нужен.
Для работы с настоящей базой создайте `web/.env.local` по образцу `.env.example`:

```
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

Publishable-ключ предназначен для браузера — доступ к данным ограничивают RLS-политики.
Секретный ключ и пароль базы в сайт не попадают.

## Публикация на GitHub Pages

Workflow `.github/workflows/web-deploy.yml` собирает и публикует сайт при каждом изменении
`web/` в `main`. Один раз нужно:

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. **Settings → Secrets and variables → Actions → Variables**: `SUPABASE_URL` и
   `SUPABASE_PUBLISHABLE_KEY`.
3. В Supabase: **Authentication → URL Configuration** — `Site URL` =
   `https://<пользователь>.github.io/<репозиторий>/`, в `Redirect URLs` добавить
   `https://<пользователь>.github.io/<репозиторий>/**` и `http://localhost:3000/**`
   (ссылка из письма подтверждения ведёт обратно на сайт).

При сборке `scripts/sync-species.mjs` обновляет снимок базы знаний `src/data/species.json`
из Supabase; без переменных используется сохранённый снимок.

## Публикация на своём домене (SpaceWeb)

Workflow `.github/workflows/deploy-spaceweb.yml` после каждого изменения `web/` в `main` собирает
сайт для корня домена и выкладывает его по SSH (`rsync`). GitHub Pages продолжает работать
параллельно. Один раз:

1. **Доступ по SSH** — проще всего по паролю, можно с телефона: в GitHub (Settings → Secrets and
   variables → Actions → Secrets) добавить секрет `SPACEWEB_PASSWORD` — пароль SSH из панели
   SpaceWeb. Надёжнее ключ: `ssh-keygen -t ed25519 -f spaceweb_deploy -N ""` на компьютере,
   `spaceweb_deploy.pub` — в панель SpaceWeb → SSH-доступ, `spaceweb_deploy` — в секрет
   `SPACEWEB_SSH_KEY` (если заданы оба, используется ключ).
2. **Переменные** (Settings → Secrets and variables → Actions → Variables): `SPACEWEB_HOST`,
   `SPACEWEB_USER`, `SPACEWEB_PATH` (папка сайта, например `~/example.ru/public_html`), при
   нестандартном порте — `SPACEWEB_PORT`. Папка должна быть отдельной: лишние файлы в ней удаляются.
3. **Домен и HTTPS** — в панели SpaceWeb привязать домен к этой папке и включить бесплатный
   SSL-сертификат с перенаправлением на HTTPS.
4. **Supabase** → Authentication → URL Configuration: `Site URL` = `https://<домен>/`, в
   `Redirect URLs` добавить `https://<домен>/**` — иначе ссылки из писем подтверждения поведут
   на старый адрес.
5. Запустить Actions → deploy-spaceweb → Run workflow (или дождаться следующего изменения в `main`).

**Откат:** Run workflow и в поле `ref` указать коммит или тег прошлой версии.
`public/.htaccess` задаёт страницу 404 и кэширование: файлы сборки кэшируются надолго,
страницы — нет, поэтому новая версия видна сразу.

## Фото, грунты и своё фото растения

- **Фото видов** — с Wikimedia Commons (миграция `*_species_photos.sql`): сайт показывает миниатюры
  Commons и подписывает автора и лицензию со ссылкой на страницу файла, как требуют CC BY / CC BY-SA.
- **Грунты** — справочник `soil_mixes` (22 рецепта: ароидный, кактусовый, для орхидей, кислый для
  вересковых…), каждому виду назначен рецепт и, где нужно, поправка. На странице вида — схема:
  разрез горшка с дренажом и мульчей, полоса пропорций, влагоёмкость, воздух, pH и калькулятор
  «сколько смешать» на объём горшка; все рецепты — на странице `/plants/soil/`.
- **Своё фото обязательно.** Растение в коллекцию добавляется только со снимком, сделанным камерой
  прямо на сайте (`getUserMedia`): поля выбора файла нет. Это не криптографическая гарантия —
  технически подкованный человек может подменить поток камеры, — но обычная загрузка картинки из
  интернета или галереи невозможна.

## Новости

Вкладка «Новости» собирает статьи из RSS-лент на русском, английском, немецком, французском и
испанском (таблица `news_sources`, сбор раз в час). Можно выбрать языки и включить автоперевод:

- статья открывается прямо на сайте в «режиме чтения» — Edge Function `news-reader` скачивает
  страницу источника и отдаёт только текст и картинки;
- в Chrome перевод делает встроенный переводчик браузера (Translator API) прямо на странице,
  без отправки текста на сервер;
- в остальных браузерах — кнопка «Открыть в переводе» (Google Переводчик) или перевод страницы
  в меню браузера.

## Устройство

Зависимости идут сверху вниз: `app → components → lib/queries → lib/data → lib/domain`.
Подробно — в [docs/plant-app/ARCHITECTURE.md](../docs/plant-app/ARCHITECTURE.md).

```
src/
  app/                    маршруты (App Router); страница собирает компоненты своего раздела
    page.tsx, login/      главная для гостя, вход и регистрация
    (app)/today/          «Сегодня»: кольца дня, задачи ухода
    (app)/garden/         коллекция, карточка растения (?id=), новое растение, «Что с растением?»
    (app)/feed/           сообщество: дневники, «Помощь», новости, новая запись
    (app)/market/         барахолка: объявление, форма, розыгрыши (contest/)
    (app)/messages/       переписка по объявлениям
    (app)/people/         поиск садоводов и профиль
    (app)/plants/         база знаний, страницы видов /plants/<slug>/, грунты
    (app)/profile/        мой профиль, «Хочу», уведомления
    (app)/achievements/   уровни и достижения
    (app)/shop/           витрина магазина (?id=) и кабинет /shop/manage/
    (app)/admin/shops/    проверка заявок магазинов (администратор)
  components/
    ui/                   UI-кит: кнопки, поля, листы, кольца, тосты
    plant-card/           блоки карточки растения
    new-plant/            части формы «Новое растение»
    feed/                 записи, вопросы, комментарии
    shop-manage/          кабинет магазина
    shops/                «Где купить», «Хочу», список магазинов
    diagnose/             «Что с растением?»: фото и симптомы
    contests/             розыгрыши барахолки
  lib/
    domain/               предметная логика без React и сети (интервалы ухода — как SQL-функции)
    data/repositories.ts  контракты репозиториев
    data/supabase/        реализация на Supabase — по файлу на раздел
    data/demo/            демо-режим в браузере с тем же интерфейсом
    queries.ts            хуки данных (TanStack Query)
  data/                   снимки базы знаний и грунтов
```

## Проверки

```bash
npm run format         # Prettier (format:check — только проверить)
npm run lint           # ESLint
npm run knip           # неиспользуемые файлы, экспорты и зависимости
npm run typecheck      # TypeScript
npm test               # логика: интервалы, достижения, прайс, диагностика, демо-режим (vitest)
npm run build          # статический сайт в out/
npm run e2e            # сценарии в браузере на компьютере и телефоне (Playwright)
```
